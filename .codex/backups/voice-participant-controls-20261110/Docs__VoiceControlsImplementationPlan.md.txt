# Voice Controls Implementation Plan

## Scope and sequence

Implement and review one stage at a time. Preserve the working Vivox proximity route and Unity environment reverb throughout.

1. **Local speech activity HUD (implemented):** a reusable microphone icon with smooth idle/speaking opacity, a red muted state and a gray unavailable state. Read the local Vivox participant and actual transmission state; do not open another microphone or change voice processing.
2. **Transmission settings (implemented):** open microphone or push-to-talk, configurable binding, saved preference and safe release across focus loss/channel recovery.
3. **In-game participant settings:** room membership and display names, listener-local volume/mute, and explicit composition with proximity mute so distance updates cannot undo a manual choice.
4. **Intensity measurement prototype:** measure quiet/normal/loud speech, test background noise and automatic gain control, then define calibration and envelope smoothing before using intensity as gameplay input.
5. **Dynamic proximity:** derive a bounded range from sender-side calibrated intensity and share only that small value through gameplay networking. Keep received audio on Vivox and apply listener-local volume after distance attenuation. Test matching standalone builds with different microphones.

## Stage 1 checkpoint and setup

Checkpoint: `.codex/backups/voice-activity-hud-20261110/` contains the affected saved-on-disk sources before implementation. Do not save or replace the user's open scenes.

- Add a read-only local activity snapshot to `VivoxVoiceManager`, isolated from audio playback and distance mixing.
- Instantiate `Resources/UI/VoiceActivityHUD.prefab` through `GameplaySceneRoot`, following the existing settings overlay bootstrap. Repeated bootstrap must reuse the scene's existing HUD. Non-gameplay scenes must not acquire one.
- Author the microphone as a Unity UI vector graphic so the prefab needs no external icon/font dependency. Make the indicator non-interactive and render below the settings overlay.
- Expose idle opacity, speaking color, transition time and a short visual release hold on the prefab. Use unscaled time and avoid a clock-driven blinking loop.
- Preserve the SDK's speech detection policy and participant update frequency in this stage. The activity snapshot's energy is the latest SDK value, not calibrated loudness; continuous intensity sampling belongs to stage 4.

## Stage 1 acceptance

- Speech highlights the local microphone; silence returns to a subdued idle icon.
- Mute, disabled voice, missing local participant, lost connection and disabled transmission cannot display active speech from stale SDK values.
- Remote speech and received reverb do not drive the local icon.
- Visual fading behaves consistently at different frame rates and continues when gameplay time is paused.
- Scene transitions and repeated setup do not duplicate the HUD; it does not consume pointer input.
- Compile runtime/Editor, run focused activity/HUD tests and existing voice-output regressions, and inspect a rendered preview without connecting voice or capturing a microphone.

## Stage 2 checkpoint and setup

Checkpoint: `.codex/backups/voice-transmission-settings-20261110/` preserves stage 1 and the affected saved settings UI before implementation. Do not save the open gameplay scene.

- Add `Voice Mode` (Open Microphone / Push to Talk) and `Push-to-Talk Key` to the shared settings prefab used by both the Settings scene and the in-game overlay. Default to open microphone and keyboard V; save both choices in local PlayerPrefs.
- Control only microphone input through the synchronous initialized Vivox mute/unmute APIs. Gate input before joining a channel and reconcile after joining/recovery. Never initialize Vivox or acquire a microphone just to configure settings.
- Close input on focus loss, application pause, disconnect, manager disable and key capture. Push-to-talk requires a release before another press after any interruption, binding change or mode change.
- Rebinding accepts keyboard keys, waits for initiating keys to be released, and cancels on Escape, focus loss or closing the menu. Escape must cancel capture without also closing the in-game settings overlay. Ordinary settings use keeps voice available; key capture temporarily closes input in either mode.
- Feed the existing activity HUD with the effective input gate so blocked transmission cannot show stale speech. Preserve received voice proximity/reverb and all listener-local output settings.
- Validate stateful hold/release/recovery scenarios, persistence, rebind lifecycle and shared UI wiring, then rerun existing activity/output regressions and render the settings UI. Live transport still needs matching client builds.
