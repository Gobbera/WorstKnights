# Voice Controls Implementation Plan

## Scope and sequence

Implement and review one stage at a time. Preserve the working Vivox proximity route and Unity environment reverb throughout.

1. **Local speech activity HUD (implemented):** a reusable microphone icon with smooth idle/speaking opacity, a red muted state and a gray unavailable state. Read the local Vivox participant and actual transmission state; do not open another microphone or change voice processing.
2. **Transmission settings (implemented):** open microphone or push-to-talk, configurable binding, saved preference and safe release across focus loss/channel recovery.
3. **In-game participant settings (implemented):** room membership and display names, listener-local volume/mute, and explicit composition with proximity mute so distance updates cannot undo a manual choice.
4. **Intensity measurement prototype (implemented; live microphone review pending):** calibrate silence/quiet/normal/loud speech, inspect automatic gain status, reject overlapping levels and smooth the local meter before using intensity as gameplay input.
5. **Dynamic proximity (implemented; rebuilt-client listening review pending):** derive a bounded range from sender-side calibrated intensity and share only that small value through gameplay networking. Keep received audio on Vivox and apply listener-local volume after distance attenuation. The microphone-test dialog also provides optional local playback. Test matching standalone builds with different microphones.

## Stage 4 follow-up: sensitive microphone readings

The initial uncalibrated meter could label quiet speech as Loud because it used arbitrary absolute anchors. Ratio-based noise/separation checks could also reject clearly separated observations near the top of the SDK's bounded energy scale. Checkpoint: `.codex/backups/voice-intensity-sensitive-input-20261110/`.

- Show input energy while uncalibrated or collecting calibration, reserving Quiet/Normal/Loud classification for a completed profile.
- Derive usable anchor spacing from the observed range and reject overlap without requiring each already-high value to be 15% larger. Interpolate directly between observed SDK energy anchors; do not assume the SDK's normalized VU value is linear PCM amplitude.
- Derive a collection threshold from measured silence and its variation so low speech is not rejected merely because the silence value is high. Guided speech steps can collect clear energy above that threshold even when the speech detector misses soft speech.
- Show measured step values and a specific failure reason so compressed/saturated readings can be distinguished from an uncalibrated scale. Preserve prior profiles and the working microphone/output settings.
- The user's follow-up confirmed automatic input level On and completed calibration still reading Loud for quiet speech. Add an explicit saved On/Off control for Vivox automatic gain, guarded by SDK initialization/login and unavailable when unsupported. Preserve SDK defaults until the user chooses a value; show that switching affects sent voice volume and requires calibration in the new context.
- Validate high-offset signals, soft speech, real noise variation, narrow/overlapping levels, raw-meter presentation, and the existing input/voice regressions.
