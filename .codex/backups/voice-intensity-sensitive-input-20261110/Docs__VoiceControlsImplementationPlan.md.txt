# Voice Controls Implementation Plan

## Scope and sequence

Implement and review one stage at a time. Preserve the working Vivox proximity route and Unity environment reverb throughout.

1. **Local speech activity HUD (implemented):** a reusable microphone icon with smooth idle/speaking opacity, a red muted state and a gray unavailable state. Read the local Vivox participant and actual transmission state; do not open another microphone or change voice processing.
2. **Transmission settings (implemented):** open microphone or push-to-talk, configurable binding, saved preference and safe release across focus loss/channel recovery.
3. **In-game participant settings (implemented):** room membership and display names, listener-local volume/mute, and explicit composition with proximity mute so distance updates cannot undo a manual choice.
4. **Intensity measurement prototype (implemented; live microphone review pending):** calibrate silence/quiet/normal/loud speech, inspect automatic gain status, reject overlapping levels and smooth the local meter before using intensity as gameplay input.
5. **Dynamic proximity:** derive a bounded range from sender-side calibrated intensity and share only that small value through gameplay networking. Keep received audio on Vivox and apply listener-local volume after distance attenuation. Test matching standalone builds with different microphones.

- Preserve the SDK's speech detection policy and participant update frequency in this stage. The activity snapshot's energy is the latest SDK value, not calibrated loudness; continuous intensity sampling belongs to stage 4.

- Mute, disabled voice, missing local participant, lost connection and disabled transmission cannot display active speech from stale SDK values.
- Remote speech and received reverb do not drive the local icon.
- Visual fading behaves consistently at different frame rates and continues when gameplay time is paused.
- Scene transitions and repeated setup do not duplicate the HUD; it does not consume pointer input.
- Compile runtime/Editor, run focused activity/HUD tests and existing voice-output regressions, and inspect a rendered preview without connecting voice or capturing a microphone.

## Stage 2 checkpoint and setup

Checkpoint: `.codex/backups/voice-transmission-settings-20261110/` preserves stage 1 and the affected saved settings UI before implementation. Do not save the open gameplay scene.

- Add `Voice Mode` (Open Microphone / Push to Talk) and `Push-to-Talk Key` to the shared settings prefab used by both the Settings scene and the in-game overlay. Default to open microphone and keyboard V; save both choices in local PlayerPrefs.
- Control only microphone input through the synchronous initialized Vivox mute/unmute APIs. Gate input before joining a channel and reconcile after joining/recovery. Never initialize Vivox or acquire a microphone just to configure settings.
- Close input on focus loss, application pause, disconnect, manager disable and key capture. Push-to-talk requires a release before another press after any interruption, binding change or mode change.
- Rebinding accepts keyboard keys, waits for initiating keys to be released, and cancels on Escape, focus loss or closing the menu. Escape must cancel capture without also closing the in-game settings overlay. Ordinary settings use keeps voice available; key capture temporarily closes input in either mode.
- Feed the existing activity HUD with the effective input gate so blocked transmission cannot show stale speech. Preserve received voice proximity/reverb and all listener-local output settings.
- Validate stateful hold/release/recovery scenarios, persistence, rebind lifecycle and shared UI wiring, then rerun existing activity/output regressions and render the settings UI. Live transport still needs matching client builds.

## Stage 3 checkpoint and setup

Checkpoint: `.codex/backups/voice-participant-controls-20261110/` preserves the current voice/UI sources and saved settings prefab. Preserve the microphone login guard and open gameplay scenes.

- Add a scrollable `Players in Room` section to shared settings, visible only while in a Photon room. List remote room members by actor identity, including members whose Vivox identity/connection is still pending. Never key controls by display name.
- Each row has a name, voice connection status, listener-local volume slider (0–100%, default 100%) and mute/unmute button. Preserve the slider when muted. Hide the local player; reconcile joining/leaving and identity publication while the menu is open.
- Store choices locally in the persistent voice manager for the running game session. Bind pending actor edits to the published Vivox identity and retain known-identity choices across voice/Photon reconnects. Reset actor associations when joining a new room so reused actor numbers cannot inherit another player's settings. Do not add network traffic or store transient identities in PlayerPrefs.
- Keep proximity gain and distance mute separate from listener preferences. Combine distance mute, manual mute and zero volume before SDK playback; apply the same user gain to Unity Audio Taps after distance attenuation. Cache SDK requests per participant instance and restore preferences on new participant objects after reconnect.
- Preserve the current distance curve/range, output-device mute, native positional fallback, reverb route and input/PTT behavior. Unresolved simulated-proximity speakers remain silent until their distance is known.
- Validate membership/identity rebinding, independent listeners, manual mute surviving distance resets, unchanged audible boundaries, source gain/reverb and shared UI callbacks. Render a synthetic multi-player preview without connecting voice or capturing a microphone.

## Stage 4 checkpoint and setup

Checkpoint: `.codex/backups/voice-intensity-calibration-20261110/` preserves the saved voice/settings sources before this stage. Do not change voice range or listener mixing.

- Request ten-per-second Vivox participant updates at login and measure only the local participant's existing audio-energy metadata. Do not start an additional microphone, echo input locally, override PTT or change SDK gain/noise processing.
- Add a microphone-test dialog to settings with a smoothed intensity meter and quiet/normal/loud classification. Show when input is unavailable and how to hold the configured PTT key. The dialog requires an existing connected voice session; opening settings alone must not initialize voice.
- Guide calibration through silence, quiet speech, normal speech and comfortably louder speech. Collect timed samples with noise rejection and robust percentiles. Pause collection while PTT/input is closed; reject absent speech or insufficient separation. Failed/canceled attempts preserve the previous valid profile.
- Persist calibration per effective microphone and SDK input gain/automatic-gain/noise-processing context. Reset the envelope on device/context changes, disconnect and mute. Display automatic-level status without changing it; report compressed or overlapping measurements rather than pretending they are usable.
- Normalize against calibrated anchors, gate background noise with hysteresis/persistence, and use distinct attack/release smoothing. Expose the local result for the later range stage, but do not publish it or consume it for proximity yet.
- Validate deterministic signals, background noise, brief spikes, pauses/mute, frame rates, failed/retried calibration, profile persistence and dialog lifecycle. Inspect rendered settings/dialog previews without recording a microphone. Real-device calibration remains a user listening/input check.
